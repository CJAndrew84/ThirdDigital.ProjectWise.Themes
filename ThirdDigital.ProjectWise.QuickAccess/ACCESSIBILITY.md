# Quick Access keyboard and icon review

Reviewed the first prototype, commit `0a94251e4ebb156b2cc91fac144ebbd7f625694c`, against the reported Explorer keyboard failure and screenshot. This review covers the companion Quick Access module. It does not establish conformance of ProjectWise Explorer, its SDK controls or Themes.

## Findings and changes

| Finding in the prototype | Impact | Change |
| --- | --- | --- |
| Only toolbar commands and the query edit had explicit Enter handling. Mode, navigation and Start Search buttons depended on a dialog manager in a normal MFC frame. | Enter could leave a visible, focused action inoperable; a synthetic `BM_CLICK` did not exercise the missing key translation. | Handle Enter before host translation and at the native control boundary. Keep native Space behaviour for ordinary buttons. |
| The floating window used `WS_EX_NOACTIVATE` and always returned `MA_NOACTIVATE`. | Interactive edits/buttons lived in a window configured to avoid activation. This is a focus-integration risk in the real host. | Allow normal activation; refresh the SDK selection context before mouse activation. Mark nested control containers with `WS_EX_CONTROLPARENT`. |
| The focus outline and command activation relied on the toolbar's hot item, which also changes with pointer hover/exit. | Moving the pointer could erase the focus indication or change which command Enter executed. | Keep an explicit keyboard command target, preserve it on hover/exit, invalidate on focus changes and announce command focus through MSAA. |
| Only command buttons scrolled into view. Search edit and Start Search could be outside the clipped page. | A keyboard user could focus a completely hidden control (2.4.11). | Reveal search controls when focus moves to them. |
| F6 handling ignored Ctrl/Alt; Alt+R also matched Ctrl+Alt+R. | Explorer's Ctrl+F6 and AltGr combinations could be intercepted. | Match shortcut modifiers precisely and leave native editing/address keys alone. |
| Activation keydowns were handled independently, including repeats after dispatch changed focus. | Holding Enter/Space could repeat an action or leak the held key to newly focused content. | Consume repeated handled activation keys and their release in the UI-thread message hook. |
| Refresh used a short GDI arc; Check Out/In had similar small padlocks; Details/Manage Views used identical geometry. | Incomplete or ambiguous symbols at normal size. | Use complete Bezier refresh arrows, opposite document arrows, an open lock for Free and distinct configuration/layout silhouettes. Rounded geometric pens scale with DPI. Retain all text labels. |
| Checked state depended on a subtle tinted background. | The selected state could be difficult to distinguish. | Add a contrasting underline while preserving native checked state. |
| Back/Forward/Up availability was inferred from selection menus and then overwritten by the main menu's potentially stale state. Navigation dispatch sent a frame command and always reported success. | Buttons could remain disabled despite usable history/parents, or report dispatch success without verifying an SDK navigation result. | Query the document-list navigator's enabled flag, count and position. Use SDK MoveBack/MoveForward with automatic selection and check the returned item. Up selects the tree parent using the SDK DSC selector and checks its result. Fall back to the main document list if no active list is available while using the ribbon. |
| Address registration or synchronization errors returned failure from the same callback that enabled all three navigation buttons. | An address-specific failure disabled otherwise healthy navigation. | Refresh navigation and address readiness independently, with modal and history/parent guards. Log numeric history/button state changes for host diagnostics. |
| CI covered Themes but did not build or run Quick Access. | The prototype's existing checks did not protect its separate solution. | Add an independent Windows x86 build/run job with no proprietary SDK dependency. |

Disabled controls are exempt from the contrast requirements in 1.4.3/1.4.11. The new icons nevertheless use a minimum 3:1 outline contrast for readability. Enabled text uses 4.5:1, and symbols, focus outlines and selected-state markers use 3:1. Contrast helpers and rendered focus pixels are checked; these thresholds alone are not a complete accessibility assessment.

## Automated regression coverage

The role-based Admin page shares the contextual-page implementation with Workflow. Tests cover independent/coexisting tabs, stable native tab indices, keyboard entry/activation, disabled New User in ordinary sessions, stale datasource/user/permission rejection and visible Home fallback when a role is lost. New User uses a labeled native account-type dropdown, defaulting to Federated identity. Its email label/hint follows the selected type. Logical mode expands the form to show two native password edits; federated mode hides/disables them and removes them from keyboard traversal. Native tests verify the labels, traversal order, masking, type-switch clearing, credential/identity validation, callback payload, error/exception recovery, cancellation and duplicate-submission guard with fake accounts. Both form modes have generated previews. Real server rights, stored account/identity types and login are not exercised by CI.

Classic UI recovery is reachable through the main Tools menu and ribbon. Native checks damage an essential ribbon control, exercise the deferred failure callback and verify content bounds are restored. A native menu/frame fixture verifies restoration of hidden docked/floating toolbars, preservation of visible bars, disabled optional bars, idempotence and exclusion of Customize/unrelated actions. Preference reads/writes are tested and the previous preference is restored. This covers handled module failures, not a process crash or a DLL that never loads; original toolbars are never hidden by the module.

Interface and View use labeled native dropdown lists on View. Regression checks cover accessible names, option/current-value synchronization, keyboard and native selection notifications, permission and stale-context rejection, narrow-window focus visibility, popup-list mouse handling, Escape cancellation, unavailable SDK queries and destruction during refresh/dispatch. Browsing an open list retains its position; only a committed choice dispatches. SDK enumeration and synchronization with the actual Classic toolbar still require the Explorer acceptance pass.

Show all versions is a native toolbar check-style button on View, with a full accessible label and visible checked underline. Tests cover keyboard End/Enter/Space, matching and externally changed host state, rejected/unavailable settings, inactive-tab dispatch and the wider target. The SDK adapter uses ProjectWise's existing user setting and document-window notification; live native-control synchronization and setting restrictions require Explorer acceptance.

The conditional Workflow tab uses native owner-drawn buttons with complete accessible names and native enabled/disabled roles. Its actions form one keyboard group: Tab/Shift+Tab leaves the group, arrows/Home/End select an enabled action, Enter/Space activates it, and focused actions scroll into view. Removing the selected Workflow tab dismisses its popup, selects Home and restores visible tab focus. Every dispatch revalidates datasource/folder/workflow/selection and the operation's current native ID, label, kind and enabled state.

Additional checks exercise standard versus WRE native menu extraction without relying on translated submenu captions, inherited disabled menu state, excluding final-status/unrelated commands, menu mnemonics, duplicate/removed/reused command IDs, conditional tab lifecycle, keyboard activation and scroll visibility, stale selections and permissions, modal blocking, and destruction during workflow refresh/execution. Real WRE extension registration, native confirmation/audit comments and actual workflow transitions require the Explorer acceptance pass.

The native check executable exercises queued `WM_KEYDOWN`/`WM_KEYUP` messages through the real UI-thread hook as well as native control dispatch. Checks include tab selection, Enter on mode/navigation/search controls, focus return, holding Enter across a host focus change and nested message loop, modifier preservation, hover/exit isolation, newly disabled commands, narrow-window search visibility, distinct rendered icon silhouettes and a complete Refresh lower sweep. Navigation checks cover empty/single-entry/first/middle/last history, invalid and maximum positions, independent parent availability, address failures and shutdown during either refresh. Existing layout, selection, command gating, popup and shutdown checks remain.

The CI job compiles the ribbon and Version stacks native controls into a fake-host executable. It does not compile the licensed SDK adapters (`Module.cpp`, `VersionStacksAdapter.cpp`, `NotificationAdapter.cpp`) or validate real Explorer integration.

The optional Version stacks report list retains native multiselection, focus and column text. Explicit accessible row names include numeric sequence; descriptions identify the visible-version count, expanded/collapsed presentation and arrow-key instructions. Right/Left and native Expand/Collapse all buttons operate the stacks. A collapsed selected child moves selection/focus to its parent so document operations cannot silently target hidden history. Native checks cover these behaviors, inaccessible/filtered newer versions, identity-based grouping, stale-context rejection and a keyboard-accessible Classic fallback after read errors. Hierarchical state announcements, tab traversal into/out of the real Explorer container, all standard document commands, context menus and live native-selection synchronization still require target-installation and screen-reader acceptance. No tree-grid UIA provider or whole-application conformance is claimed.

## Reported workflow/admin regressions and notifications

A workflow-enabled folder keeps its tab visible even when the selected native row omits the workflow display flag. Native action availability and forced metadata checks guard dispatch. An external host modal disables actions while preserving contextual tabs and the selected page; status text also supplies the page's accessible name. WRE-only branches can be identified by the native Change State popup ID even when standard leaves are replaced.

New User exposes actual SDK error/detail text in a native read-only multiline edit with scrolling and copy selection. Error 58004 is classified as invalid data, without assuming the cause is permissions. Native notification/basket dialogs default focus to Not now/Close, use native radios, a multi-select review list, labeled note/recipient fields, read-only generated preview and explicit draft-launch/copy/park controls. Removal updates the generated document/link section while retaining the covering note. Context changes prevent compose dispatch. Windows-protected basket persistence, same-document/version deduplication, source/account isolation and no external send during tests are covered in the check executable. Real PWE hooks, HTTPS generation, Teams/email handlers, Narrator/NVDA and DPI acceptance remain outstanding.
