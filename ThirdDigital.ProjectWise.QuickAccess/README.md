# ProjectWise Quick Access (prototype)

A separate solution and custom-module DLL for ProjectWise Explorer 23.06.03.12 (x86), independent of AtkinsRealis.ProjectWise.Themes. Neither the Themes solution nor its installer needs this module. The two modules can be registered together.

## Tabbed ribbon

- **Contextual pages:** Workflow follows the folder/document selection; **DataSource Admin** follows the active datasource user's Administrator or Restricted Administrator membership. Contextual tabs share command rendering, keyboard navigation, focus return and stale-context checks. They retain stable tab identities when another contextual page appears or disappears. Tab widths account for their labels and current font, with native tooltips when the window is narrow.
- **DataSource Admin:** **New User** and **Users and Groups**, with no separate administrative login button. The tab is visible only to Administrator/Restricted Administrator members in the active datasource. Open either command directly: an existing administrative connection is reused, or the module establishes administrative access as part of that action. The current connection's SDK-issued authentication token is passed to a silent native administrative sign-in, reusing the datasource handle and locking datasource/user selection. It does not use another account's saved automatic-login preferences or cache credentials. If the token is unavailable/rejected, ProjectWise can show its native credential prompt within the action; cancelling stops the action. Authentication happens only when a command needs it, never from tab refresh or ordinary datasource login. Datasource, user, roles, command availability and administrative setup are checked again after sign-in and before creation; stale or denied access stops the action. A session that expires while New User is open can be re-established on submission. Restricted Administrators retain the server's Users-node granular limits. Users and Groups opens the existing SDK management dialog.
- **Project Admin:** visible to members of a global access userlist named exactly `*BA` (the star is literal), or any global access userlist ending in `-Project Administrator` (the prefix is a wildcard). Comparison is ordinal and case-insensitive. The prefix is not matched to a work-area number or folder name. Direct membership, membership through user groups and nested access userlists are resolved; ownership alone and private mailing/address-book lists do not qualify. This tab is independent of DataSource Admin and can coexist with it and Workflow. It contains **New User**, **Users and Lists**, **Project Properties** and **Project Access**. User creation still requires the current user's datasource administrative rights, uses the same automatic session setup and credential form, and rechecks project eligibility at submission. It does not add a new user to a project/list automatically. Users and Lists opens the native datasource-wide User / Group Management dialog; native ownership and server permissions determine what may be changed. Project Properties and Project Access target the nearest work area containing the current folder, including the work area itself. Selecting a document does not remove the tab. Outside a work area those two actions are disabled, while list/user actions retain their separate permissions. Native dialogs and the server enforce project permissions; the tab's membership rule grants no server rights.
- **New User:** the native dialog displays the target datasource and an explicit **Account type** selector, defaulting to **Federated identity (Bentley IMS)**. Enter the account name, description and the existing IMS identity's primary email. That email is supplied as both the account email and federated identity; the SDK receives the federated user type, not a logical account with only a contact email. **Logical (ProjectWise password)** instead shows masked Password/Repeat password fields and makes contact email optional. Both fields must match; the public SDK limit is 43 characters and the server's password policy still applies. Passwords are not trimmed, logged or persisted by the form; owned request buffers are cleared after submission, and controls are cleared on an error, cancellation or a switch to federated mode. Re-enter both fields after a failed attempt. Creation rechecks the original datasource/user/session and command availability; server errors remain visible. No privileges or group membership are added by the ribbon. Windows/domain accounts and multiple login identities remain available through **Users and Groups**.
- **Tools > Re-enable Classic UI:** available in Explorer's main Tools menu before ribbon creation and on the ribbon's Tools page. It stops the ribbon, releases its docked content area, and restores available native toolbar commands through Explorer's own handlers, including detected floating bars. Already-visible bars stay on; unavailable optional bars are skipped. The choice is saved per Windows user under `HKCU\Software\AtkinsRealis\ProjectWise\UI\UseClassicUI`. **View > Ribbon** or **Tools > Quick Access Toolbar** clears that preference and retries the ribbon.
- **Failure recovery:** native toolbars are never hidden by this module. Handled creation, docking/startup timeout, layout/DPI and C++ window-handler failures stop the ribbon and select Classic UI. A UI-thread health check detects missing essential controls or a lost ribbon window. Recovery does not depend on datasource menu queries or an administrative session. If the module DLL cannot load at all, its code cannot run recovery, but the original native UI remains untouched. Process termination, memory corruption and failures inside Explorer or other extensions are outside this recovery boundary. If toolbar verification fails, use the native **View > Toolbar** menu; no arbitrary hidden child windows or unrelated menu actions are exposed.
- An **AtkinsRealis - Quick Access** toolbar that starts docked above Explorer's content pane. Right-click it and choose **Float** or **Dock at top**. Drag the docked left-hand grip to float it; double-click the floating title bar or drag it to the top of Explorer to dock again. This is a separate top docking row, not a replacement for Bentley's native toolbar/ribbon docking system.
- **Home:** New Folder, Add Documents, Check Out, Check In, Free, Properties, Refresh, Open and New Document.
- **View:** Thumbnails, Large Icons, Small Icons, List, Details, Manage Views, **Show all versions**, and labeled **Interface** and **View** dropdown selectors. Interface selects Classic Explorer's datasource-level attribute interface; View selects the document-list column view for the current folder. These are native Windows dropdown lists with names and current values supplied by the SDK. The old Interface dialog button is replaced when selector callbacks are present; Manage Views remains available.
- Selector lists refresh after datasource/list/folder changes, with a five-second options cache and live current-value/permission polling. Focus/opening and commits request fresh choices. Applying a selection revalidates the context, choice ID/name and enabled state. Interface changes use the SDK's active-interface setter and existing interface-change notification; View changes use the document-list view API and existing view-settings notification. The module does not replace Classic's notification receivers or change administrator folder/default-view definitions. Native control changes synchronize back to the ribbon. An open dropdown retains its browsing position while the context remains valid; Escape cancels it before closing a minimized ribbon popup. Tab/Shift+Tab reaches both selectors, F4/Alt+Down opens their lists, Enter applies a choice, and focused controls scroll into view.
- **Show all versions** is a native check-style button with a stacked-document icon and a visible checked underline. It reads and toggles ProjectWise's `AADMS_PAR_DIS_SHOW_VERSION` user setting through the SDK, then requests a document-window refresh. The same client-side setting is used by Explorer's native control; a change made there is reflected on the ribbon's next refresh. This changes the current session's setting without saving unrelated pending user settings. No datasource/user/list or a failed setting query disables the button; a rejected setter does not invent a new checked state. It is keyboard accessible with the other View commands, and the full label has a wider button.
- **Search:** Advanced Search, Find in Folder, a query field and Start Search. Press Enter in the query field to run ProjectWise Simple Search in the active document list. This uses the SDK's query-string API, not SQL.
- **Tools:** Local Documents (Local Document Organizer), User Settings, Wizard Manager and Help Index.
- **Workflow (conditional):** appears when the current folder has a workflow and the selected rows, if any, are documents in that folder with a workflow. Standard workflows show **Next**, **Previous** and **Change** using their native labels and permissions. When the native **Change State** menu contains WRE operations, those operations replace the standard transitions, in their configured menu order. Final-status commands are not added to this tab. The folder workflow keeps the tab visible while selection determines action availability. Mixed or unavailable selections retain the tab with guidance and no executable actions. The list-row workflow flag is a display hint; invocation verifies actual document workflow/version metadata, and native menus supply permissions. External modal dialogs temporarily disable actions without closing the selected contextual tab.
- Workflow actions are read from an SDK-initialised Document menu with workflow/custom-extension flags. Labels, hidden operations and disabled states follow ProjectWise's menu; operation names are not hard-coded. Dispatch uses the SDK's document-command API so extension callbacks, WRE confirmation/audit-comment dialogs and normal cancellation are retained. Datasource, folder, workflow and selected document/version identity are checked again before executing; a stale, renamed, removed or newly disabled action is rejected. No state-change SQL or direct WRE action implementation is used.
- Workflow folder metadata is cached for up to five seconds; selection/menu state follows the normal half-second refresh. Execution forces a fresh folder-workflow check. If Workflow disappears while selected, Home is selected and focus returns to the visible tab strip. Native workflow buttons form one Tab stop, with arrows/Home/End between enabled actions and automatic horizontal scrolling on narrow windows.
- The command panel is a **child page inside the native tab control**, not a toolbar beside a tabs-only strip. A dedicated **navigation row beneath it** contains Back, Forward, Up and the SDK's editable ProjectWise address control. This row stays visible when commands are minimized or the ribbon is hidden. In minimized mode, temporary commands open below the navigation row without moving it.
- The address control synchronizes with Explorer's tree and active document list and follows its current location without overwriting an address being edited. Explorer's original navigation toolbar and main-address registration are left intact; existing native toolbars and third-party commands, including Transmittals, remain available.
- **Back/Forward** use the SDK document-list navigator and its history count/current position. **Up** selects the selected tree item's parent with the SDK's DSC-tree selection function. Navigation is independent of the document command menus and address-bar synchronization: an address refresh failure can disable the address field without disabling healthy navigation buttons. Back/Forward correctly disable at the beginning/end of history, and Up disables at a tree root. A main-document-list fallback handles ribbon focus when there is no active list. Debug output records changes to numeric history position/count and button availability without recording locations or document names.
- Original 32 logical-pixel line icons with rounded strokes: stacked pages for Add Documents, opposite document arrows for Check Out/In, an open lock for Free, complete circular arrows for Refresh, and distinct layout/configuration symbols. Readable labels, flat tabs with an active underline, grouped command captions and hover highlights remain. Checked commands have an underline as well as their native accessible checked state. Commands remain 64 logical pixels high; typography starts at 11 pt and respects larger system message fonts. Colours follow Windows system colours, including the active Themes palette. Enabled and disabled icons retain at least 3:1 contrast without copying Bentley artwork.
- Buttons are disabled if their SDK-defined command is absent or disabled in Explorer's SDK-initialised menus. The ProjectWise menu layouts are loaded before their state is initialized. Select a folder in the tree or documents in the active document list first. Some buttons will not apply to a particular selection.
- Availability updates every half-second while visible and is checked again on clicking. The selection context is retained while using tabs and the query field. An Explorer modal dialog disables actions. Only commands on the selected tab can be dispatched. Narrow docked windows provide horizontal scrolling for commands that do not fit.
- Commands use the SDK's published identifiers and Explorer's normal `WM_COMMAND` routing, rather than performing check-in/out or document operations directly. The last focused selection control is retained while using the toolbar and restored before synchronous command dispatch. **Add Documents** maps to the Create Multiple Documents command and its normal wizard.
- The ribbon opens expanded each time Explorer starts. **Maximise** pins the tabs and full-size command panel; **Minimise** leaves tabs and navigation; **Hide** leaves navigation only. These controls affect the ribbon, not the Explorer window.
- Clicking a minimized tab temporarily opens its commands over the content pane. Choosing a command, clicking outside, pressing Escape or leaving Explorer dismisses them without permanently expanding the ribbon. Double-clicking a tab switches between expanded and minimized modes.
- Use **View > Ribbon** or **Tools > Quick Access Toolbar** to restore a hidden ribbon to its previous expanded/minimized mode. The floating window's close button also hides the ribbon. Dock position, tab and display mode are retained during the session only, not saved across Explorer restarts.

This is a custom tabbed command bar, not Microsoft's Ribbon framework or a replacement for Explorer's native toolbar docking system. It does not change Themes settings. The native SDK address control and search input retain their Windows/ProjectWise rendering.

## Workflow notifications and basket

**Tools > Prompt after workflow state changes** enables the client observer for the current Explorer session. Native menu-command and document-state pre/post/failure hooks capture the affected versions; ribbon and version-stack commands also provide a command boundary. Hooks observe operations without changing their parameters, outcome or WRE processing. Before/after verification uses SDK document reads, not a datasource-wide audit query. There are at most 64 documents per captured action, 128 pending documents and eight document probes per two-second timer tick, with increasing backoff and a two-minute observation window.

A prompt follows a confirmed change: two consistent reads and a six-second quiet interval coalesce intermediate WRE states. Unchanged/cancelled actions produce no prompt; failed actions may still report genuinely committed partial changes. Read/access failures and changed version identities suppress stale observations. Main-window modals and another foreground application defer prompts. Server-side WRE can finish after the client command returns; the observer continues checking captured documents during its bounded window. Very late server changes, inaccessible post-transition documents, unobserved third-party/worker-thread actions, and changes while Explorer is closed require a server-side notification service for reliable coverage. This client correlation is not an audit-proof statement of who performed every concurrent server update.

After reviewing a change, choose **Add to basket**, **Open Teams**, **Open email**, **Copy message** or **Not now**. For a run of approvals, enable **Tools > Park workflow notifications automatically**. **Tools > Notification basket...** reviews the accumulated document/version entries, with Remove selected, Clear all and an optional covering message. One entry per document/version retains its latest observed transition; other versions stay separate. The basket is scoped to datasource and ProjectWise user, protected with Windows user DPAPI, and saved in the user's registry profile across Explorer restarts. Source/account changes switch baskets. Saved items describe the user's recorded activity rather than claiming the document remains in that state. A failed save is reported, and unsaved records remain in memory while Explorer stays open. Existing unreadable saved data is preserved. Capacity is 250 entries; review/clear before adding more. Basket review remains available when automatic prompting or the ribbon is disabled.

Document links use **`https://pwlink.bentley.com/link?ds=...&doc=...`**. `doc=` identifies the document; `fld=` is reserved for folder links. Native SDK link generation supplies routing context, and older `datasource/objectId/workAreaId/projectId` URLs are normalized to `ds/doc/wa/p`. Existing `s` routing is retained, with no hard-coded WSG endpoint, work area or connected project. If the native link helper is unavailable, confirmed datasource/document GUID metadata supplies the supported minimal universal document link. Legacy `pw:` links are never substituted.

The independent **Open links in** selector supports the application chooser (no `app`), Explorer (`app=pwe`), Web (`app=web`) and Web View (`app=webview`). Web links require real `wa`/`p` context; missing context blocks that target rather than fabricating IDs. Existing native routing parameters are preserved. Standard Get Link semantics determine which document version opens; the observed version label/sequence is retained separately and no undocumented version query is invented. Bentley documents the [current link parameters](https://bentleysystems.service-now.com/community?id=kb_article_view&sysparm_article=KB0046378).

Teams uses Microsoft's chat compose deep link with user-entered Entra sign-in addresses/UPNs; email uses the default `mailto:` handler. **These open drafts; the user reviews recipients and presses Send in the destination app.** No Graph app registration, stored mail password, automatic external send or claimed delivery receipt is involved. Recipients are entered for each message. Large baskets copy the complete message and open a recipient-addressed draft for pasting, avoiding URL-length truncation; the button explicitly says Copy + open. Items stay in the basket after opening a draft because the add-on cannot verify a later Send action. Clear them when finished. Only document links/observed transitions/covering notes are stored; recipients are not retained.

Microsoft's [Teams chat deep-link documentation](https://learn.microsoft.com/en-us/microsoftteams/platform/concepts/build-and-test/deep-link-teams) and Bentley's [Get HTTPS Link help](https://docs.bentley.com/LiveContent/web/ProjectWise%20Explorer-v2025/Help/en/topics/1688349/GUID-E9F63F59-0F65-489A-ACE7-BA162977A324.html) describe the platform behavior. CI tests the observer model, real native prompt/basket controls, protected storage and fake launch callbacks. The SDK hook registration, actual asynchronous WRE behavior and generated HTTPS URLs still need acceptance in Explorer; tests do not send messages.

## Administrative error details

New User shows the SDK's immediate error code, message and extended detail in a selectable, scrollable response field. Error **58004 is invalid data**; it is no longer presented as proof of insufficient Users-node permissions. The public `aaApi_CreateUser2` compatibility call supplies the selected `AADMS_STSUSER`/`AADMS_DMSUSER` type and the identity email or confirmed password in the same SDK request. This intentionally replaces the record-only `aaApi_CreateUser3` call: the newer per-identity exports are not declared in the supplied public SDK, so the module does not guess their signatures or leave identity provisioning to a second step. The SDK documents CreateUser2 as obsolete for managing multiple identities; this form creates one login type. The federated provider is left to the datasource's IMS configuration and normal first-login/synchronization resolution. The form does not create a Bentley IMS account or store an IMS password. Blank optional fields are passed as null, and a stale earlier error is cleared before creation. Retry on a disposable datasource and compare account type and login behavior with Administrator; the screenshot alone does not prove which field or policy caused 58004.

## Document version stacks (optional view)

The SDK registers an additional **Version stacks** tab in the Document List Area. Choose that native list-area tab to use it, and enable **Show all versions** on the ribbon's View tab to include permitted historical versions. The original flat document list remains available. The main **View > Version stacks** menu shows/hides the additional tab; **Classic list** in the stacked view hides it and returns control to Explorer. Re-enable it with that View menu and choose its tab again. These choices are session-only. Classic UI recovery also hides the additional views.

- Each family has one selectable parent: the **highest numeric version sequence currently visible to the user**, followed by older visible versions in descending sequence when expanded. Version labels are displayed, not used for sorting. If permissions or the current filter omit the active/newest version, the highest remaining visible version becomes the parent. A parent can therefore be a historical version. An earlier version reactivated as the current document does not outrank a higher visible numeric sequence.
- Families use ProjectWise's original-document identity within a datasource/folder/user context. Identical file/document names never merge separate documents. Counts describe only the rows in the visible list; omitted versions contribute no names, counts or parent rows. Only already-visible native rows are projected into the view. A folder-scoped SDK metadata lookup supplies original-document IDs and numeric sequences; there is no unrestricted datasource scan or direct SQL.
- Click a parent's Versions cell or use **Right/Left Arrow** to expand/collapse. **Expand all** and **Collapse all** are native keyboard-accessible buttons. The other columns and status images are copied from the native list, with a numeric Sequence column appended. Families retain the order of their first native row; use the original list to change sorting/filtering/column configuration, then return to Version stacks. Column header sorting and drag/drop are not implemented by this additional view.
- Native report-list multiselection maps each displayed row back to exactly one native document/version. Selecting a parent never selects its history. Collapsing selected children moves selection/focus to the visible parent, preserving selections in other families. A selected historical row in Explorer is automatically expanded when opening the stacked view. Enter/double-click and the context menu use SDK-initialized availability and native command dispatch. Native SDK confirmation, access checks and cancellation remain authoritative. Stale datasource/user/folder/row identity or selection rejects dispatch and refreshes the view.
- This first implementation supports **single-folder document lists in the main Explorer window**. Cross-folder searches, sets, extra attribute rows and contexts with unavailable/inconsistent metadata show an explanation and **Classic list**, with no stale actionable rows. Snapshots are bounded to 20,000 visible rows, 250,000 cells and eight million characters; larger lists fall back to Classic. Turning Show all versions off leaves individual current rows and requires no extra version-metadata lookup. The module does not delete, hide or reorder rows inside Bentley's original control. No folder/search/filter setting is changed to manufacture additional results.

The model and real Windows control are checked in CI with a fake list host, including invisible newer versions, same-name documents, numeric ordering, multiselection, collapse selection safety, keyboard activation, accessible names/descriptions and stale-context/read failures. `VersionStacksAdapter.cpp` requires the licensed SDK and is not compiled in public CI. Registration, live list/selection notifications, native tab switching, document operations/WRE, large-folder performance and assistive-technology behavior must be accepted in the target Explorer installation before deployment. This is an opt-in draft feature, not a verified modification of Classic's built-in flat view.

## Accessibility

The ribbon implements **WCAG 2.2 AA-aligned desktop accessibility features**, not a declaration of full WCAG conformance for ProjectWise or its SDK controls:

- **Keyboard:** Alt+R restores/focuses the tabs. Left/Right Arrow and Home/End select tabs; Down Arrow or Enter opens commands. Tab/Shift+Tab traverses visible, enabled controls; commands form a single toolbar stop with Left/Right Arrow, Home/End and Enter/Space activation. Enter also activates Maximise, Minimise, Hide, Back, Forward, Up and Start Search without relying on the host's dialog manager. Space uses native button handling. Commands and search controls selected by keyboard scroll into view. F6 cycles between Explorer content, tabs and navigation; Shift+F6 reverses this. Escape dismisses temporary commands and returns focus to tabs, or returns to Explorer content when no popup is open. Ctrl+F1 switches expanded/minimized mode. Shift+F10 or the Menu key opens docking/display commands at the focused control. Ctrl+F6, AltGr and native address/editing keys remain available to Explorer. Modal Explorer dialogs block ribbon shortcuts.
- **Focus:** solid, DPI-scaled focus outlines use at least 3:1 contrast. Pointer hover/exit cannot change the keyboard command target or erase its outline. Availability refresh moves focus from a newly disabled command to an enabled command or the tabs. Collapse/hide and popup dismissal move focus to a visible control; Tab and F6 can leave the ribbon. The floating ribbon accepts activation and keyboard focus, retaining Explorer's selection context before it does so. Held activation keys are consumed until release to prevent repeated actions after focus changes.
- **Screen readers:** native tabs, toolbar buttons, edit/combo controls and buttons preserve their standard accessible roles/states. Windows accessibility annotations supply explicit location, search, ribbon-action and page names/descriptions; page names and selection/state notifications update with the UI. Icon-only navigation buttons retain accessible Back/Forward/Up names. These native MSAA providers are available to UI Automation through Windows' accessibility bridge.
- **Contrast:** custom-painted text enforces at least 4.5:1; enabled symbols, active-tab indicators and focus outlines enforce at least 3:1. Unreadable palette colours fall back to black/white without changing the saved theme. Disabled commands also expose their native disabled state, not just a colour difference. Windows contrast-theme colours and live theme changes are respected.
- **Targets and scaling:** mode/navigation buttons and tabs have at least 24 logical-pixel targets; standard command buttons are 112 by 64 logical pixels, Show all versions is 160 by 64, and Workflow actions are 160 by 80. The native address selection field is requested at 24 logical pixels high. Layout and drawing scale with window DPI. There are no animations or automatic document actions.

Automated native checks cover contrast reference values/thresholds, accessible names, measured targets, real queued keyboard routing, focus traversal/return, narrow-window search visibility, held-key dispatch and icon silhouettes. GitHub Actions builds and runs this separate check executable without the proprietary SDK. **Narrator/NVDA, native SDK address accessibility, Campbell/light/Windows contrast themes, 200% display scaling and real Explorer focus/command routing still require manual acceptance.** WCAG is a web-content standard; use [WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/) when applying its criteria to this desktop software. See the [review and acceptance matrix](ACCESSIBILITY.md); an end-to-end assessment must also cover the host, native dialogs and third-party controls.

## Build

Use Visual Studio 2022 or newer with the v143 Desktop C++ tools, a Windows 10/11 SDK, and the separately licensed ProjectWise SDK with Win32 libraries. No MFC, ATL, MinHook or .NET dependency is added by Quick Access. The x86 Visual C++ runtime matching the compiler is required on the target machine.

Open `AtkinsRealis.ProjectWise.QuickAccess.sln` in the repository root, not the Themes solution. From a Developer PowerShell in the repository root:

```powershell
$env:PWSDKDir = 'C:\Program Files\Bentley\ProjectWise\SDK'
msbuild .\AtkinsRealis.ProjectWise.QuickAccess.sln -t:Build -p:Configuration=Release -p:Platform=x86
.\ThirdDigital.ProjectWise.QuickAccess\Checks\out\Win32\Release\bin\AtkinsRealis.ProjectWise.QuickAccess.Checks.exe
```

DLL: `ThirdDigital.ProjectWise.QuickAccess\out\Win32\Release\bin\AtkinsRealis.ProjectWise.QuickAccess.dll`.

The native checks use a fake host and real Windows controls. They verify labels, dimensions, actual tab-page ownership and containment, the four permanent tabs and conditional Workflow tab, native standard/WRE menu extraction, selection/permission revalidation, keyboard workflow activation, inactive-command gating, nested native tab/button notifications, expanded/minimized/hidden transitions, temporary-popup dismissal, persistent navigation layout/dispatch, history-boundary availability, independent navigation/address failures, accessibility features, query submission, selection-context retention, docking, scrolling, content resizing/restoration and safe shutdown without accessing a datasource or changing documents. They do **not** prove Explorer's SDK menu initialization, WRE extension loading and callbacks, navigator/history integration, parent selection, native address synchronization, search execution or command routing works for every selection. Test the prototype against a disposable datasource before using commands on production documents, particularly **Free**, which invokes Explorer's normal operation and may discard local changes.

## Register for local development

There is no Quick Access MSI in this first version. Build the Release DLL, close Explorer, then run the following in an **administrator PowerShell**, from the repository root:

```powershell
.\ThirdDigital.ProjectWise.QuickAccess\Register-Module.ps1 -Action Register
```

The script registers the full build-output path under the **32-bit** registry view:

`HKLM\SOFTWARE\WOW6432Node\Bentley\ProjectWise\CustomModules\ThirdDigital.ProjectWise.QuickAccess`

It checks for Explorer 23.06.03.12 or a later 23.06.03 build and an x86 DLL. It does not copy files, edit Bentley files, change the Themes registration, close applications or install anything else. Keep the DLL at the registered location. To use a stable deployment folder, copy the DLL there yourself and pass `-LibraryPath 'C:\YourFolder\AtkinsRealis.ProjectWise.QuickAccess.dll'`. `-WhatIf` previews registration without writing registry values.

Restart Explorer. The toolbar should appear shortly after its main window is ready. Its DLL remains loaded until Explorer exits; close Explorer before rebuilding or changing registration. Diagnostics use `OutputDebugString` with the prefix `ProjectWise Quick Access`.

## Remove

Close Explorer and run in administrator PowerShell:

```powershell
.\ThirdDigital.ProjectWise.QuickAccess\Register-Module.ps1 -Action Unregister
```

Only this module's registry key is removed. Themes, existing Explorer toolbars and the DLL file are left untouched.
